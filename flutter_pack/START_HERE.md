# interMove 0.8 — booking prototype

Начните с **START_V08.md**: исправленные настройки, компактное оформление и OSM.
Ниже сохранена инструкция по основному бронированию.

## Установить обновление

Это набор исходников поверх вашего Flutter-проекта, не готовый установщик.
Сначала сохраните командные изменения в Git и сделайте копию базы intermove.sqlite.
Остановите старый Python-сервер и Flutter. Перенесите lib, backend, test и website из архива.
Не удаляйте свои windows/android/macos и pubspec.yaml. При собственных изменениях lib
используйте сравнение Git, а не слепую замену. Старые серверные аккаунты сохраняются.

Новых Flutter-зависимостей нет. pubspec.example.yaml — только пример зависимостей,
его не нужно автоматически переименовывать поверх вашего pubspec.yaml.

Терминал 1, из папки проекта:

```powershell
python backend/server.py --local-dev
```

Терминал 2:

```powershell
flutter pub get
flutter run -d windows --dart-define=BACKEND_URL=http://127.0.0.1:8787
```

На Mac используйте python3 и flutter run -d macos. Сохраните ранее добавленный
com.apple.security.network.client=true в обоих macOS entitlement-файлах.
Android для общей базы использует HTTPS-адрес, не компьютерный 127.0.0.1; см. HTTPS_TEAM.md.

На карте появилась кнопка билета «Билеты и поездки / Book journeys».
Автобусы, поезда и межгород также открывают новый раздел. В нём сверху выбираются
Search / Bookings / Notifications / Profile / Drivers / Delivery / Management.
Management появляется после входа оператором/администратором, права проверяются сервером.

Для нового расписания НЕ нужен ключ ORS. Оно работает с демонстрационными остановками,
текстовым маршрутом и схемой. Обычная карта, адреса по клику, пешие/велосипедные пути
сохранены. Дорожная геометрия по-прежнему требует ORS_API_KEY.
При желании добавьте к команде Flutter --dart-define=ORS_API_KEY=ваш_ключ, не сохраняйте его в Git.

## Что реализовано

- Поиск городского/междугороднего автобуса, поезда и такси по времени и 1–4 пассажирам.
- До трёх участков; остановки пересадок, время ожидания, фильтры, сортировка цены/длительности.
- Отдельные требования: без ступенек, помощь при посадке, складная коляска / оставаться в ней.
  Проверяются транспорт, обе остановки каждого участка и пересадки. Неизвестные обязательные
  характеристики исключают вариант. Животные, переноска, размер и предпочтение водителя.
- Пять минут резерва; места поезда/междугороднего автобуса, вместимость городского автобуса,
  интервалы занятости машины. Конкурирующие операции проходят через транзакции.
- Тестовая оплата approved / declined / timeout / approved_then_failed (проверка возврата одобрения).
  Реальных карт и денег нет. Одна оплата подтверждает все участки или не подтверждает ни одного.
- Защита от повторного checkout/платежа. Прерванное оформление сохраняется в локальной базе;
  после входа в Bookings есть Resume interrupted checkout. Не создавайте новый запрос вместо повтора.
- Билеты с DEMO-меткой, история, отмена с показом возврата, возврат незапущенных участков
  при несовместимом изменении оператора, альтернативы и замена будущего бронирования.
- Сохранённые уведомления с переходом к поездке и признаком прочтения.
- Кабинеты оператора/администратора: рейсы, тарифы, вместимость, доступность, задержки,
  отмены; административные аккаунты/операторы/водители/автомобили/остановки и журнал.
- Избранные водители и одна оценка 1–5 на завершённый участок такси.
- Доставка: отправитель/получатель/контакты/размеры/вес, лимиты S/M/L, тестовый расчёт,
  подтверждение и последовательность статусов через администратора-симулятор.
- Фиксированные демонстрационные курсы USD/EUR, расчёт и оплата всегда KZT.
- Переключатель EN/RU/KK для основных элементов нового раздела; выбор сохраняется.
  Полный перевод всех сообщений и старой карты ещё не завершён: часть текста остаётся английской/русской.
- Рамка аватара и форма меток карты сохраняются локально и в профиле при явном сохранении.
- Информационный website/index.html; без фиктивных ссылок на ещё не собранные установщики.

## Быстро показать основной сценарий

1. Откройте Book journeys → Search. Начало Aktobe Central, конец Khromtau Centre.
2. Оставьте предложенную дату: расписание создаётся на следующие семь дней при первом
   запуске НОВОЙ базы. Рейсы помечены DEMO, не являются реальным расписанием.
3. All modes, 1 пассажир, buffer 15 → Find journeys.
4. Выберите вариант city_bus → train → taxi. Войдите/зарегистрируйтесь по email.
5. Проверьте имя, email, участки, цену и отмену → Reserve for 5 minutes.
6. Выберите approved → Confirm mock payment. Появится общий номер и билеты участков.
7. Bookings → Open → Cancel booking: сначала сумма, затем явное подтверждение.
8. Повторите с declined / timeout / approved_then_failed: подтверждённой поездки быть не должно.

Имена городов и координаты не означают проверенные перевозки. Дорожный маршрут карты
и расписание нового раздела — разные источники: произвольный адрес не подменяется молча
остановкой. В новом планировщике пользователь явно выбирает остановки набора данных.

## Администратор / оператор

```powershell
python backend/server.py --create-staff admin
python backend/server.py --create-staff operator
```

Введите разные email и свои тестовые пароли. Пароль не выводится.
Команды используйте из той же папки или с тем же --db, что и сервер.
Management → Operators: назначьте accountId операторского аккаунта.
Сначала Management → Accounts and roles покажет идентификаторы аккаунтов.
Оператор видит только закреплённые рейсы. Обычный пассажир не может стать админом
подменой поля role при регистрации.

В редакторе время — YYYY-MM-DD HH:mm UTC+05; fareCents — тиыны (100 = 1 ₸).
Для задержки измените start/end и status=delayed; для отмены status=cancelled.
Доступность с «—» означает неизвестно, а не «поддерживается».
Для обновления при открытом другом клиенте нажмите Refresh: push-уведомления ОС не реализованы,
используются требуемые сохраняемые in-app notifications.

Администратор может найти бронирование по номеру и выполнить Simulator: advance next leg:
confirmed → in_progress → completed, затем следующий участок. Это явные тестовые события,
не реальное движение машины. Для Delivery администратор меняет requested → accepted/rejected
→ picked_up → delivered. Отдельного приложения водителя нет; используется разрешённый
спецификацией административный симулятор.

## Проверка и границы готовности

В папке backend находятся результаты 33 выполненных тестов, замер поиска и проверка
фонового освобождения резерва. Они относятся к этой Linux-среде, не к вашим устройствам.

```powershell
python -m unittest discover -s backend -v
python backend/performance.py
flutter analyze
flutter test test/intermove_logic_test.dart test/demo_dispatch_test.dart test/journey_hub_test.dart
```

Flutter-анализ, Flutter-тесты и сборки здесь НЕ выполнены: автоматическая проверка
безопасности заблокировала установку/запуск Flutter из-за попытки запроса к служебному
облачному metadata endpoint. Обход не предпринимался. Синтаксис Dart проверен парсером,
но это не заменяет проверку типов. Запустите команды Flutter на своём ноутбуке.

Нельзя считать все требования принятыми только потому, что функции написаны.
REQUIREMENTS_STATUS.md показывает реализацию и оставшиеся проверки. В частности,
нужны Windows/Android-приёмка, полный перевод, клавиатура/TalkBack/200% масштаб/контраст,
выходные APK/Windows-сборки и реальное пользовательское исследование. Дизайн также базовый.

## Данные и повторяемость

База совместима с аккаунтами 0.5; новые таблицы добавляются автоматически. Не запускайте
старый и новый сервер одновременно с одной базой. Сделайте резервную копию при остановленном сервере.
Рейсы не переносятся на новые даты автоматически, чтобы не менять купленные билеты.
Для свежего чистого демо: остановите сервер и выберите НОВОЕ имя базы:

```powershell
python backend/server.py --local-dev --db demo_fresh.sqlite
```

Это отдельная база: потребуется создать тестовые аккаунты заново. Старая не удаляется.
Производительный fixture создаётся и удаляется только во временной папке.
Пароли, SQLite-файлы, приватные ключи сертификатов не коммитьте; добавьте правила из
GIT_IGNORE_ADDITIONS.txt. История локальных черновиков остаётся отдельной от серверных билетов.
