# InterMove 0.3 — Photon, маршруты, тариф и выбор поездки

## Установка

Это обновление последнего проекта из чата, не самостоятельный Flutter-проект.
Сначала сохрани свои изменения через Git или сделай копию lib.

1. Останови Flutter (q в терминале).
2. Скопируй содержимое lib из архива в свою lib с заменой совпадающих файлов.
   Не создавай вложенную lib/lib. Все 7 Dart-файлов нужны.
3. В папке проекта с pubspec.yaml выполни:

```powershell
flutter pub add flutter_map latlong2 url_launcher http path path_provider cryptography "sqlite3:^3.7.1"
flutter run -d windows
```

Папки windows/android и pubspec.yaml из проекта не удаляй.
Для sqlite3 3.x нужен совместимый свежий Dart/Flutter. Если зависимости не разрешаются,
пришли flutter --version и ошибку; не понижай sqlite3 до 2.x наугад.

## Ключи

Photon API: ключ НЕ НУЖЕН. Регистрация НЕ НУЖНА. Вводишь адрес → «Найти адрес».
По умолчанию поиск ограничен Актобе и окрестностями, чтобы не выбирать одноимённые посёлки.
Для межгорода сними галочку «Искать только в Актобе» и укажи другой город в запросе.

openrouteservice: нужен отдельный ключ для автомобильных, пеших и велосипедных
маршрутов. Поле намеренно оставлено пустым, как ты просил.
Позже: шестерёнка справа сверху → «Ключ openrouteservice» → «Применить».
Ключ из окна хранится только до выхода из приложения.
Альтернатива для разработки: --dart-define=ORS_API_KEY=...; не коммить ключ в исходники.
Место пустой настройки: lib/app_config.dart, routingApiKey.
Кабинет: https://account.heigit.org/ . Актуальная бесплатная квота — в кабинете.
Используется новый endpoint https://api.heigit.org/openrouteservice/v2 .

Без ключа работают карта, Photon, профили, параметры поездки, выбор A/B и загрузка
автобусных остановок. Без ключа дорожный маршрут, его расстояние и цена не вычисляются.
Прямая линия между A/B не выдаётся за настоящий маршрут. Фальшивого тарифа нет.

## Маршрут A → B

По умолчанию выбран автомобильный режим. Выбор обеих точек запускает расчёт
с небольшой задержкой, чтобы не слать запрос на каждый быстрый щелчок.
Первая точка карты — A, следующая — B. Для изменения A нажми значок карты в её поле.
Изменение текста очищает прежнюю координату: новый адрес надо подтвердить результатом.
Смена вида транспорта перестраивает путь. Поздние ответы старых запросов игнорируются.

Реальный shortest-path поиск по дорожному графу выполняется сервисом openrouteservice,
а не локальной реализацией Дейкстры в приложении. Отправляется preference: shortest.
Профили:
- такси, доставка, межгород: driving-car;
- пешком: foot-walking;
- велосипед: cycling-regular.

Пешеходный и велосипедный пути могут отличаться от автомобильного и друг от друга.
Дворы, тропы, запреты и доступность учитываются в пределах данных карты. Нельзя
обещать проезд/проход через любой двор. Велосипедное время не просто делится на число:
сервис пересчитывает маршрут с велосипедными ограничениями. В отдельных случаях
из-за объезда велосипедный путь не будет быстрее. ETA не учитывает текущие пробки.
Маршрут рисуется синей линией. Близкие к дорогам точки работают надёжнее точек внутри домов.

## Тариф

Принято предположение: 350 ₸ за каждые НАЧАТЫЕ 500 метров.
Формула: ceil(длина дорожного маршрута в метрах / 500) * 350.

500 м → 350 ₸; 501 м → 700 ₸; 1000 м → 700 ₸; 1001 м → 1050 ₸.
Тариф применяется к такси, автомобильному межгороду и доставке.
Для пешком/велосипеда тарифа нет. Для автобуса/трамвая тариф неизвестен и не выдумывается.
Доплаты за животных, коляску, время ожидания и межгород пока не заданы.
Поменять расчёт можно в fareForMeters() в lib/route_service.dart.

## Нижняя панель

Шесть горизонтальных карточек: обычное такси, автобусы, трамвай/метро, межгород,
доставка, пешком/велосипед. Карточки прокручиваются горизонтально.
При выборе карточки список затухает со сдвигом вниз, появляется панель выбранного режима.
«Все виды» возвращает карточки. На маленьком окне панели имеют ограниченную высоту
и прокрутку. Поиск можно скрыть крестиком и вернуть верхней кнопкой лупы.

Такси:
- доступная перевозка в коляске;
- поездка с животным;
- сочетание обеих потребностей;
- предпочтение по водителю: женщина / мужчина / без разницы.

Это требования к машине/водителю, а не подтверждение наличия подходящей машины.
В межгороде добавлено число пассажиров. Доставка сейчас автомобильная.

«Сохранить заявку · демо» сохраняет выбранные параметры и цену в SQLite.
Водитель не вызывается и оплата не списывается. Вызов реального водителя потребует
серверной части и базы доступных водителей. Гость тоже может сохранить заявку.
Существующие локальные аккаунты сохранены: используется прежнее имя базы.

## Автобусы и трамвай/метро — границы реализации

Из публичного Overpass API загружаются реальные OSM-отношения маршрутов PTv2
рядом с отправлением: bus/share_taxi/trolleybus или tram/subway/light_rail.
Никаких выдуманных маршрутов или остановок в комплекте нет.

Сначала проверяется порядок остановок и ищутся прямые варианты без пересадок:
A → ближайшая подходящая остановка посадки → остановка высадки → B.
Остановка посадки должна идти раньше высадки в направлении маршрута.
Учитываются ограничения stop_entry_only/stop_exit_only.
Кандидаты ищутся в пределах 1.5 км по прямой от A и B. Это предварительный отбор:
дорога пешком может быть длиннее или недоступна. После выбора варианта сервис
openrouteservice проверяет оба пеших участка по настоящему пешеходному графу.
Если пеший путь длиннее 2.5 км, выводится предупреждение, а не скрывается проблема.

Зелёные линии — проверенные пешие участки. Тонкая оранжевая линия — СХЕМА между
остановками, НЕ точная трасса автобуса по улицам. Есть названия посадки и высадки.
Маршруты без упорядоченных остановок PTv2, а также платформы только в виде OSM ways
пока не используются. Поэтому отсутствие результата не доказывает отсутствие транспорта.

Полнота/актуальность OSM в Актобе не подтверждена. Нет GTFS, расписаний, пересадок,
ожидания, онлайн-координат автобусов и точной автобусной геометрии.
Это первый рабочий поиск прямых кандидатов по открытым данным, НЕ полный аналог 2ГИС.
Чтобы завершить транспортный планировщик, нужны проверенные данные перевозчиков/GTFS.
Нельзя выдавать автомобильный маршрут за автобусный или генерировать номера маршрутов.

## Файлы

- main.dart — карта, панели, анимации, настройки поездки, состояние запросов.
- address_service.dart — Photon, разбор адресов, ограничение частоты и кеш.
- route_service.dart — маршруты openrouteservice и тариф.
- transit_service.dart — Overpass, остановки, прямые варианты общественного транспорта.
- app_config.dart — адреса сервисов и пустая настройка ключа маршрутов.
- local_store.dart — SQLite, хеши паролей, локальные заявки.
- profile_panel.dart — вход/регистрация/приветствие.

## Проверка

В архиве test/intermove_logic_test.dart: тарифные границы, профили,
порядок координат, расстояние из ответа сервиса, направление автобусных остановок,
запрет посадки на exit_only. Скопируй файл в test и запусти:

```powershell
flutter test test/intermove_logic_test.dart
```

Старый шаблонный test/widget_test.dart со счётчиком/MyApp больше не подходит:
обнови или удали именно его. Свои остальные тесты сохрани.

Ручная проверка:
1. Гостевой запуск, вход/выход и повторный вход старым аккаунтом.
2. Поиск известного адреса в Photon, установка A/B мышью, перестановка точек.
3. Без ключа маршрут выдаёт понятное сообщение, цена не показывается.
4. С ключом: авто → пешком → велосипед; сравнить линии и ETA.
5. Быстро поменять B/режим: старый ответ не должен вернуть старую линию.
6. Такси: оба спецпараметра и выбор пола водителя; сохранить демозаявку.
7. Автобусы: найденные остановки либо честное сообщение о недостатке данных.
8. Проверить слабое соединение/ошибочный ключ и изменение размера окна.

Синтаксис всех Dart-файлов проверен парсером Tree-sitter без синтаксических ошибок;
это не заменяет проверку типов и компиляцию. SQL сохранения заявки проверен на SQLite.
Flutter SDK отсутствует в среде подготовки. Flutter-сборка, flutter analyze,
тесты Dart и запросы с реальным ключом здесь не запускались. Не считать их пройденными.
Photon проверен живыми запросами с ограничением района Актобе: получены реальные результаты.
Проверочный запрос Overpass завершился тайм-аутом; наличие пригодных автобусных данных
и работа транспортного поиска на реальных данных Актобе НЕ подтверждены.

## Сеть и хранение

Photon — публичный demo endpoint: умеренная нагрузка, без гарантий доступности.
Один запрос за раз, поиск по кнопке, пауза между запросами, небольшой кеш в памяти.
Overpass — явный поиск транспорта с кешем по району; без постоянного опроса.
Для публичного запуска нужны подходящие квоты/хостинг, общий сервер и контроль нагрузки.
Профили остаются локальными, пароли — PBKDF2 с солью. Это не общая серверная авторизация.
Ключ маршрутов не надо публиковать в GitHub; клиентский ключ не является серверным секретом.

Для Android release в android/app/src/main/AndroidManifest.xml внутри <manifest>
перед <application> добавь, если отсутствует:
<uses-permission android:name="android.permission.INTERNET" />
Целевые платформы: Windows и Android. Для Web требуется другая настройка SQLite.
