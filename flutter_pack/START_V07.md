# InterMove 0.7 — карта, общественный транспорт, история такси

Это обновление исходников поверх вашего проекта 0.6. Не готовый APK/EXE.

## Установить

1. Сохраните текущие изменения в Git. Остановите Flutter и сервер, скопируйте SQLite-базу в резервную папку.
2. Перенесите **все** файлы `lib`, `backend`, `test`, `website` из архива в проект. При командных изменениях объединяйте через Git diff.
3. Не заменяйте свои `windows`, `android`, `macos`, `pubspec.yaml`. Новых зависимостей нет; `pubspec.example.yaml` только справочный.
4. Из корня проекта запустите:

```powershell
python backend/server.py --local-dev
```

Во втором терминале:

```powershell
flutter pub get
flutter analyze
flutter run -d windows --dart-define=BACKEND_URL=http://127.0.0.1:8787
```

Для Mac — `python3` и `-d macos`. Для общей базы и Android см. `HTTPS_TEAM.md`.
Используйте тот же путь к базе / параметр `--db`, что раньше. Новые таблицы и DEMO-рейсы
добавляются один раз; аккаунты и существующие билеты сохраняются. Первый запуск 0.7
добавляет расписание на следующие семь дней. Для нового чистого демо после истечения дат
используйте новый файл базы, а не удаляйте рабочий.

## Общественный транспорт

- Кнопки автобуса, поездов и межгорода ведут на экран с картой. На ширине от 1000 px:
  карта **62% слева**, поиск/рейсы **38% справа**. При оформлении карта тоже остаётся.
- На узких окнах и телефоне карта сверху, прокручиваемая панель снизу.
- Поиск выбирает первый подходящий маршрут и показывает его на карте. «Показать маршрут»
  переключает между результатами. Видны даты/время, остановки, пересадки, оператор, цена и места.
- Нажмите остановку на карте для подписи и координат. В учебном наборе проверенных
  почтовых адресов нет — интерфейс сообщает об этом, а не придумывает улицу/номер дома.
- При проблемах с плитками нажмите «Без подложки»: схема и текстовый маршрут сохраняются.
- Метро/трамвай/LRT находятся в дополнительных параметрах; при выборе «Все виды» они
  включаются отдельным переключателем. Отдельный выбор режима ищет только этот режим.

### Готовые примеры

1. **Актобе → Уральск**: кнопка примера выбирает DEMO Aktobe Station → DEMO Oral rail terminal.
   Для автобуса выберите DEMO Aktobe bus terminal → DEMO Oral bus terminal и intercity_bus.
2. **Астана: поезд + городской транспорт**: поезд → такси или поезд → автобус → LRT.
   Первый вариант содержит два участка, второй три. Смотрите время и цену каждого.
3. **Демо метро + трамвай**: отдельный вымышленный набор Demo City. Это не утверждение
   о существующем трамвае/метро конкретного города. В Астане используется название LRT.
4. Городской автобус: Aktobe Central → Aktobe Station. Произвольные адреса главной карты
   пока не переводятся автоматически в ближайшие остановки: выберите их явно.

Расписания, тарифы, координаты терминалов и линии учебные. Линия — **схема связи остановок**,
не подтверждённый путь по дороге/рельсам. Актуальные реальные рейсы не загружаются.
HeiGIT не нужен для поиска этих рейсов. Старое построение автомобильных/пеших маршрутов
на главной карте по-прежнему использует ваш ORS_API_KEY.

## История такси и избранное

Сверху главной карты и нового раздела есть отдельная кнопка истории такси.

- Подтверждённые такси из общего бронирования попадают в неё автоматически, с их настоящим
  статусом: оформлено не означает «поездка уже завершена». Автобусы и поезда туда не попадают.
- На главной карте после поиска вымышленного водителя появилась кнопка **«Оформить ДЕМО-такси»**.
  Она сохраняет отдельный учебный заказ, его маршрут, стоимость и водителя. Это не билет,
  не оплата и не резерв автомобиля. Требуется вход в серверный аккаунт.
- В истории можно сохранить/удалить избранного водителя и отправить тестовый запрос.
  Офлайн-запрос ожидает выхода в сеть. Повторное нажатие не создаёт новые уведомления.
- «В сети» и доступность конкретного времени — разные вещи. Запрос/положительный ответ
  сам по себе не резервирует транспорт; обычное бронирование заново проверяет совместимость.
- Старые локальные черновики 0.4/0.5 не превращаются задним числом в поездки с вымышленным водителем.

### Проверить уведомление «водитель в сети»

1. Оформите DEMO-такси и добавьте водителя в избранное.
2. Во втором клиенте войдите администратором. Management → Drivers and vehicles → меню
   справа у нужного водителя → «DEMO: не в сети».
3. У пассажира обновите историю, нажмите «Запросить этого водителя».
4. Администратор переключает этого водителя «DEMO: в сети».
5. Пассажир получает сохранённое уведомление об избранном водителе и ответ симулятора.
   Повторное включение уже активного статуса не спамит уведомлениями.
6. Management → «DEMO: запросы водителям» позволяет принять/отклонить запрос от имени симулятора.

Статусы не случайные: ими управляет администратор. Отдельного приложения настоящего водителя нет.

## Уведомления

Кнопка колокольчика есть сверху. В новом разделе показывается число непрочитанных.
При оформлении билета уведомление содержит дату/время и направление. Также сохраняются
отмены, изменения рейсов, запросы водителям и смена статуса избранного водителя.
Нажатие открывает соответствующую поездку или историю такси и отмечает сообщение прочитанным.
В открытом новом разделе данные обновляются каждые 15 секунд и вручную кнопкой Refresh.
Это in-app уведомления; фоновые уведомления ОС при закрытом приложении не реализованы.
На главной карте колокольчик открывает список, но не показывает счётчик до открытия раздела.
