# InterMove 0.8 — настройки, компактное оформление, настоящие линии OSM

## Почему раньше работало по-разному

В 0.7 кнопка настройки ключа скрывалась у обычного пользователя при BACKEND_URL.
Без BACKEND_URL приложение включало локальные аккаунты и не могло обращаться к серверу
бронирования. Это разные режимы, не ошибка установленного Flutter.

В 0.8:
- Настройки доступны сверху всем пользователям. Административные права сервера не меняются.
- Адрес сервера можно ввести, проверить и сохранить в приложении.
- На Windows/macOS/Linux адрес по умолчанию — http://127.0.0.1:8787.
- На телефоне требуется общий HTTPS, указанный в настройках или BACKEND_URL.
- При смене адреса сессия сбрасывается, нужен новый вход. Локальные старые аккаунты не
  переносятся в серверную базу автоматически. Не отправляйте пароль от одного сервера другому.
- Приоритет адреса: сохранённая настройка → BACKEND_URL → desktop localhost.
  Если запускаете с новым --dart-define, а приложение использует старый сервер, измените сохранённый адрес.
- Пустой адрес явно включает старый локальный режим без бронирования.

## Обновить проект

Сохраните изменения команды в Git, остановите приложение/сервер и сделайте копию базы.
Перенесите **lib, backend, test, website** в проект, включая новую папку **backend/data**.
Свои pubspec.yaml и windows/android/macos не удаляйте. При собственных изменениях объедините
исходники через сравнение Git. Новых зависимостей нет.

Первый терминал, корень проекта:

```powershell
python backend/server.py --local-dev
```

Второй терминал:

```powershell
flutter pub get
flutter run -d windows
```

Теперь для локальной Windows-разработки этого достаточно: Python-сервер должен оставаться запущенным.
На Mac: python3 и flutter run -d macos. Общий HTTPS описан в HTTPS_TEAM.md; его адрес
можно вводить через настройки, пересборка с новым адресом необязательна.

Откройте шестерёнку → проверьте адрес → «Проверить соединение» → «Применить».
Для локального запуска адрес http://127.0.0.1:8787. Ключ ORS относится только к дорожным
маршрутам и не нужен для нового автобусного справочника и демонстрационного бронирования.
Ключ ORS из окна по-прежнему хранится только до закрытия приложения; адрес сервера сохраняется.

## Меньше информации на экране

На оформлении сразу видны направление, дата, цена и основной шаг. Данные пассажира
подставляются из кабинета; их можно раскрыть и изменить. Подробные остановки, места,
доступность, условия отмены и сценарии тестовой оплаты находятся в раскрывающихся разделах.
По умолчанию тестовая оплата успешная, declined/timeout доступны в «Тестовые сценарии оплаты».
Резерв по-прежнему действует пять минут; защита от повторов и возвраты сохранены.

## Автобусы OpenStreetMap

Кнопка **«Автобусы»** на главной карте теперь открывает отдельный справочник OSM.
Главные точки A/B передаются в него. Также можно выбрать точки касаниями карты.

В поставку включены реально скачанные отношения OSM:
- №15: relation 7836092 — 21 запись остановок;
- №15: relation 8477889 — 18 записей остановок;
- №1: relation 19859667 — 7 записей остановок.

Это **три записи направлений, не три разных номера** и не вся сеть Актобе.
Граница поиска: 50.18,57.05–50.40,57.40. Наличие записи OSM не подтверждает работу рейса
сегодня. Дата выгрузки показана в приложении. Адрес улицы выводится только при наличии
соответствующих OSM-тегов; остальные остановки не получают вымышленные адреса.

Проверить:
1. Откройте «Автобусы».
2. Выберите линию из списка → «Поставить A и B по концам линии».
3. Нажмите «Найти схему проезда».
4. Выберите вариант. Видны где сесть/выйти и возможная пересадка.

Поиск учитывает порядок остановок PTv2 и ограничения entry_only/exit_only; направление
не разворачивается искусственно. До/после автобуса допускается до 1200 м по прямой,
между остановками пересадки — до 250 м. Максимум одна пересадка. Это топологические
кандидаты, **не гарантия пешеходного прохода или стыковки по времени**.
В каталоге показана полная геометрия линии OSM. После выбора варианта отображается
схема выбранной последовательности остановок и пеших связей с явной подписью.

Данных расписания, реальных мест, цен и GPS в этой поставке нет. OSM-результаты не
выдаются за доступные к покупке билеты и не попадают в таблицу демонстрационных рейсов.
При обязательных требованиях доступности неизвестные характеристики дают честный no-match.

Демо-бронирование городского автобуса остаётся через «Билеты и поездки» → Mode city_bus.
Поезда и межгород продолжают использовать демонстрационные расписания 0.7.

## Работа без доступного Overpass

Сервер использует сохранённую выгрузку и проверяет её возраст. При возрасте более суток
пытается обновить через Overpass, затем резервный публичный экземпляр. При ошибке сохраняет
старые данные и показывает предупреждение. Неудачные попытки ограничены кэшем на 5 минут.
Кэш хранится рядом с SQLite как <имя-базы>.osm.json. Не удаляйте backend/data/aktobe_osm.json:
это исходный резервный снимок. Кнопка Refresh не обходит кэш и не перегружает публичный сервер.

Ручное обновление встроенного снимка с компьютера разработчика:

```powershell
python backend/urban_osm.py
```

Команда не изменяет базу бронирования. Если запрос завершился ошибкой, предыдущий снимок сохраняется.
При подготовке архива Overpass вернул ошибку/тайм-аут на геометрию; данные были скачаны
через официальный OSM API для обнаруженных relation ID. Автоматическое обновление Overpass
на вашем соединении ещё нужно проверить. GPS/задержки из этого создать нельзя.

33 серверных теста пройдены, включая направление, пересадки, неизвестную доступность,
сохранённые данные при сетевой ошибке и отсутствие изменений бронирований при чтении OSM.

служебному облачному адресу. Новые тесты настроек включены, но не запускались.

На своём компьютере:

```powershell
flutter analyze
flutter test
python -m unittest discover -s backend -v
```
